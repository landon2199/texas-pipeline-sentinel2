The plan

Find out whether vegetation and moisture next to Texas liquid pipelines differ from similar land nearby, using Sentinel-2 imagery and a pipeline written in Python.

What the project is

For GIS Day 2025, Landon buffered the Texas Railroad Commission's liquid hydrocarbon pipelines at 100, 250 and 500 m, split the buffers by ecoregion, and used Google Earth Engine to average Sentinel-2 NDVI (greenness) and a water index over each piece for March to May 2025.

That version had three limits. It covered one season, so it says nothing about change. It had no comparison area, so it cannot tell a pipeline effect from what the land is like anyway. And its IDs did not match between distances or tables, so some rows were lost or could not be compared. The Tasks page lists every problem found.

This year we rebuild it as one Python program: stable segment IDs, distance rings with a reference ring further out, finer EPA Level III ecoregions, soil class, and the same spring window for 2019 to 2025.

How we work

1

Branch and pull request

Each task gets its own branch. When it works, open a pull request and ask one teammate to review it before it joins main.

2

Data stays out of GitHub

Large tables, shapefiles and imagery live in the shared Drive folder or as Earth Engine assets. Only code, small samples and documents go in the repository.

3

Scripts run from start to finish

No step done by hand in a desktop program. If a teammate cannot rerun it from the repository, it is not finished.

The three groups

Each group delivers one report. Group A's segment layer feeds group B's extraction, and group B's results feed group C's analysis, so A and B start first and C builds its tools on sample data meanwhile.

Data and segments

One clean pipeline segment layer with stable IDs, rings and a reference ring.

  • Report: an audit of last year's tables and a description of the new segment layer.
  • Uses Python with geopandas. Works on a Mac.
  • Finds out why the polygon count exploded, and fixes it.

Earth Engine in Python

Last year's Earth Engine script, rebuilt as a documented Python program.

  • Report: the extraction method: sensor, dates, cloud mask, indices and counts.
  • Uses the Earth Engine Python API. Everyone needs a registered account.
  • First goal: reproduce last year's 250 m Deserts values.

Analysis and maps

Join the results, compare each ring with its reference, and map it.

  • Report: results by ecoregion, soil, distance and pipe diameter, with the GIS Day maps.
  • Uses Python: pandas, geopandas and a statistics package.
  • Builds and tests its tools on last year's sample tables first.

Who is in which group is on the Home page after check-in. Every task is on the Tasks page. Landon leads the team and is not in a group.

Rules

  • Never commit passwords, keys or Earth Engine credential files, The repository is public.
  • Never commit large data. Put it in the shared Drive folder and write down where it is.
  • Work on a copy of last year's data, never the original.
  • One change per pull request, reviewed by one teammate.
  • Log any AI help you use: the tool, what you asked, what it did, what you changed.
